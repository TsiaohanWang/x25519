# 第 14 章：密钥交换

> 对应论文：§4.3 椭圆曲线 Diffie-Hellman、§4.8 完成标量乘法

## 14.1 本章要回答的问题

X25519 是 **Diffie-Hellman 密钥交换**的一个具体实例：把第 2 章协议里的“群元素”换成“曲线点的 $x$ 坐标”。本章回答：

1. `x25519(out, sk, pk)` 这个函数内部到底做了什么？
2. 完整的密钥交换流程是什么？RFC 7748 的测试向量如何验证它？
3. X25519 提供哪些安全保证，不提供哪些？

## 14.2 协议流程

回顾第 2.4 节，DH 协议在两个参与者之间协商共享秘密：

```
Alice                                Bob
  |  生成私钥 a，计算 A = x25519(a, 9)   |
  |——  A ——→                          |
  |                                     |  生成私钥 b，计算 B = x25519(b, 9)
  |←——————  B ———————————————|
  |                                     |
  |  共享密钥 S = x25519(a, B)          |  共享密钥 S = x25519(b, A)
```

两者的共享密钥相等：

$$S = x25519(a, x25519(b, 9)) = x25519(b, x25519(a, 9)) = (ab) \cdot 9 \text{ 的 } x\text{ 坐标}$$

这是群运算的结合律与交换律的直接推论（第 2、4 章）。

## 14.3 x25519 函数内部

```c
void x25519(u8 *out, const u8 *sk, const u8 *pk)
{
    u8 clamped_sk[32];
    field_elem x, z, x_out, z_out, inv_z, result;

    /* 1. 钳位私钥（第 13 章） */
    memcpy(clamped_sk, sk, 32);
    clamp(clamped_sk);

    /* 2. 解包对方公钥（u 坐标），Z 坐标初始化为 1（仿射） */
    unpack25519(x, pk);
    z[0] = 1;
    for (int i = 1; i < 16; i++) z[i] = 0;

    /* 3. Montgomery 阶梯：计算 clamped_sk * (x : z)，结果在 (x_out : z_out) */
    montgomery_ladder(x_out, z_out, clamped_sk, x, z);

    /* 4. 唯一一次除法：射影 -> 仿射，x = x_out / z_out */
    finverse(inv_z, z_out);
    fmul(result, x_out, inv_z);

    /* 5. 打包成规范的 32 字节 */
    pack25519(out, result);
}
```

第 3 步的 `montgomery_ladder` 是第 12 章的内容；其余四步都是前几章现成的函数。注意 `clamp` 在 `x25519` 内部再次执行——因为调用者传入的 `sk` 可能没有钳位（RFC 7748 的 `X25519(k, u)` 定义就是“内部先解码标量（含钳位）再计算”）。钳位是幂等的，重复执行无害。

## 14.5 安全考虑

**X25519 提供**：

- **前向保密**（在协议层面）：如果使用临时密钥对（每个会话重新生成私钥），即使长期私钥泄露，过去的会话密钥仍然安全。
- **防小子群攻击**：通过钳位（第 13 章）和“检查全零输出”。

**X25519 不提供**：

- **认证**：不防中间人攻击。需要额外的认证机制（签名、证书）确认公钥属于对方。
- **密钥确认**：不能保证对方算出了相同的共享密钥。协议层需要额外的确认消息。
- **可贡献性（contributory behaviour）**：RFC 7748 §7 明确指出，由于余因子存在，如果对方发送小阶点，共享密钥可能不包含你的私钥贡献。检测方法是**检查输出是否为全零**并中止——RFC 建议用“所有字节 OR 起来是否为 0”来常数时间地检查：

```c
static int is_all_zero(const u8 *b, int len) {
    u8 acc = 0;
    for (int i = 0; i < len; ++i) acc |= b[i];
    return acc == 0;
}
```

- **KDF 要求**：X25519 的输出是共享秘密（不是均匀随机密钥），应该经过密钥派生函数（KDF）再用于加密，且 KDF 应包含双方公钥，避免第 7 节提到的“等价公钥”攻击。

## 14.7 小结

- `x25519(sk, pk)` = 钳位 + 解包 + 阶梯 + 一次除法 + 打包，五步全部来自前几章。
- RFC 7748 §5.2 直接测 `X25519(k, u)`，§6.1 测完整 DH 流程。
- X25519 提供前向保密与小子群防御，但不防中间人、不提供密钥确认；输出应经 KDF 使用，并建议检查全零输出。
