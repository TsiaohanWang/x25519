# 第 5 章：数据表示

> 对应论文：§3.1 加法与减法（表示部分）

## 5.1 本章要回答的问题

第 1 章说过，密码学要用“固定宽度”的数；第 3 章说过域元素是 255 位整数。但 C 语言的
`long long` 只有 64 位，根本放不下 $p = 2^{255} - 19$。本章回答：

1. 255 位的域元素在计算机里怎么表示？
2. 为什么要用 16 个 64 位整数存 16 位值这种“浪费”的表示？
3. `unpack25519` 和 `carry25519` 各自做了什么、为什么那样做？

## 5.2 两种表示

论文为模 $p$ 的整数维护**两种表示**：

| 表示 | 形式 | 用途 |
|------|------|------|
| 字节数组 | 32 个 `unsigned char` | 函数的输入/输出，网络传输 |
| `field_elem` | 16 个 64 位整数 | 内部算术 |

两者都采用**小端序**：数组的第 0 个元素是最低有效部分。

```c
typedef unsigned char u8;
typedef long long i64;
typedef i64 field_elem[16];
```

一个 `field_elem` 数组 $(a_0, a_1, \ldots, a_{15})$ 表示的数定义为

$$a = a_0 \cdot 2^0 + a_1 \cdot 2^{16} + a_2 \cdot 2^{32} + \cdots + a_{15} \cdot 2^{240}
\tag{1}$$

即第 $i$ 个元素是 $2^{16i}$ 位的系数。**关键**：这个定义在元素 $a_i$ 超出
$[0, 2^{16}-1]$ 甚至为负时**仍然良定义**——它只是一个加权和。我们故意允许元素“膨胀”，这是“延迟归约”（第 6 章）的前提。

## 5.3 为什么每个元素用 64 位整数来存 16 位

乍一看很浪费：16 位的数据为什么要放进 64 位的槽？原因：

1. **避免溢出**：加法和减法会产生进位/借位，乘法（第 7 章）的中间项会迅速变大。如果元素只有 16 位，一次加法就可能溢出；用 64 位槽，中间结果有巨大的余量，我们就不必每步都处理进位。
2. **简化代码**：`fadd`/`fsub` 只是简单的逐元素加减，没有任何进位逻辑。
3. **常数时间**：没有进位传播的复杂分支，循环次数固定，执行时间与数据无关。

代价是内存占用（16×8 = 128 字节 vs 32 字节），但密码学实现通常不在乎这点空间。

## 5.4 unpack25519：字节数组 → field_elem

```c
static void unpack25519(field_elem out, const u8 *in)
{
    int i;
    for (i = 0; i < 16; ++i)
        out[i] = in[2*i] + ((i64) in[2*i + 1] << 8);
    out[15] &= 0x7fff;
}
```

逻辑：每两个相邻字节组成一个 16 位 limb——`in[2*i]` 是低字节，`in[2*i+1]` 左移 8 位后是**高字节**。第 16 个 limb（最高位）再执行 `out[15] &= 0x7fff`，即把第 255 位强制清零。

**为什么要清第 255 位？**两个原因：

1. 域元素总是小于 $2^{255}$（因为 $p < 2^{255}$），所以第 255 位没有信息量；清零后任意 32 字节都对应一个合法的 $[0, 2^{255}-1]$ 的数。
2. 这与 **RFC 7748 的 `decodeUCoordinate` 完全一致**：RFC 规定接收 u 坐标时“MUST mask the most significant bit in the final byte”，目的包括兼容性（该位在其他协议里是符号位）和抗指纹识别。

注意：这个函数允许输入 $[2^{255}-19, 2^{255}-1]$ 中**未归约**的值（例如字节串
`ff ff ... 7f` 表示 $2^{255}-1 > p$）。论文明确说这无害，因为所有接受 `field_elem`
的函数都正确处理未归约输入——这是“延迟归约”哲学的体现。

## 5.5 carry25519：把元素压回 16 位

```c
static void carry25519(field_elem elem)
{
    int i;
    i64 carry;
    for (i = 0; i < 16; ++i) {
        carry = elem[i] >> 16;
        elem[i] -= carry << 16;
        if (i < 15) elem[i + 1] += carry;
        else elem[0] += 38 * carry;
    }
}
```

对每个元素 $elem[i]$ 执行三件事：

1. `carry = elem[i] >> 16`：取出高于 16 位的部分（进位/借位，可为负）。
2. `elem[i] -= carry << 16`：把 $elem[i]$ 压回 $[0, 2^{16}-1]$。（即使 $elem[i]$ 为负也正确：例如 $elem[i] = -1$，则 $carry = -1$，$elem[i] = -1 - (-1 \cdot 2^{16}) = 65535$，落在范围内。）
3. 把进位传播给相邻元素：非最后一个元素加到 `elem[i+1]`；最后一个元素（$i = 15$，代表 $2^{240}$ 位）的进位代表 $2^{256}$，由于$2^{256} = 2p + 38 \equiv 38 \pmod{2p}$，所以乘以 38 加到 `elem[0]`。

这里 `if (i < 15)` 的分支**只依赖公开的循环变量 $i$**，不依赖任何秘密数据，因此是常数时间的。

**“38” 从哪来？**见第 1.5 节：$2^{256} = 2p + 38$。把 $2^{240}$ 位的进位看成加了$2^{256}$，它等价于加了 $38$（在模 $2p$ 意义下）。这就是“神秘的 38”的完整出处，第 7 章会再次遇到它。

**一次调用够吗？**不够。`carry25519` 一次调用会把所有元素压回 16 位，但**最后一个元素回绕到 `elem[0]` 的进位可能让 `elem[0]` 再次超出范围**；第二次调用修复它，但如果 $elem[1..15]$ 都接近 `0xffff`，第二次调用可能引发级联进位使 `elem[0]`
又超界；第三次调用后级联不可能再发生（中间元素已为零）。所以：

- 确保所有元素在 $[0, 2^{16}-1]$ 内需要调用**三次**（第 9 章的 `pack25519`）；
- 但乘法（第 7 章）只需要元素足够小、不会在下次乘法中溢出，**两次**就够。

## 5.6 C 代码：完整示例

```c
#include <stdio.h>

typedef unsigned char u8;
typedef long long i64;
typedef i64 field_elem[16];

static void unpack25519(field_elem out, const u8 *in) {
    int i;
    for (i = 0; i < 16; ++i) out[i] = in[2*i] + ((i64) in[2*i + 1] << 8);
    out[15] &= 0x7fff;
}

static void carry25519(field_elem elem) {
    int i;
    i64 carry;
    for (i = 0; i < 16; ++i) {
        carry = elem[i] >> 16;
        elem[i] -= carry << 16;
        if (i < 15) elem[i + 1] += carry;
        else elem[0] += 38 * carry;
    }
}

static void print_fe(const char *name, const field_elem fe) {
    printf("%-14s", name);
    for (int i = 0; i < 16; ++i) printf("%04llx ", (unsigned long long)(fe[i] & 0xffff));
    printf("\n");
}

int main(void) {
    /* 数字 1 的 32 字节小端表示 */
    u8 one[32] = {1};
    field_elem a;
    unpack25519(a, one);
    print_fe("unpack(1)", a);          /* a[0]=1，其余 0 */

    /* 构造一个"膨胀"的元素：a[0] = 2^16 + 5（模拟加法后的进位） */
    field_elem b = {0};
    b[0] = (1LL << 16) + 5;
    printf("carry25519 前 b[0]=%lld（> 0xffff）\n", (long long)b[0]);
    carry25519(b);
    printf("carry25519 后 b[0]=%lld, b[1]=%lld\n", (long long)b[0], (long long)b[1]);
    /* 输出：b[0]=5, b[1]=1 —— 进位被正确传播 */
    return 0;
}
```

## 5.7 练习

1. 把数字 $2^{255}-1$ 写成 32 字节小端数组，`unpack25519` 之后
   `out[15]` 的值是多少？（提示：`& 0x7fff` 把最高位清掉了。）

## 5.8 小结

- 两种表示：32 字节（外部）与 16-limb `field_elem`（内部），均小端。
- 用 64 位槽存 16 位值，为“延迟归约”留出空间，避免每步进位。
- `unpack25519` 负责字节 → limb，并清零第 255 位（对应 RFC 的要求）。
- `carry25519` 把元素压回 16 位，末位进位乘 38 回绕——因为 $2^{256} \equiv 38
  \pmod{2p}$。
