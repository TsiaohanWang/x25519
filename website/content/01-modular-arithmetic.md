# 第 1 章：模运算与同余

> 对应论文：§2.1 模运算

## 1.1 本章要回答的问题

X25519 的全部计算都在"模 $p$ 的整数"上进行，其中 $p = 2^{255} - 19$ 是一个巨大的素数。
在动手写任何代码之前，我们必须先弄清三件事：

1. "模 $p$" 到底是什么意思？
2. 为什么密码学计算非要模一个大素数，而不是用普通的整数？
3. $p = 2^{255} - 19$ 这个数字特殊在哪里，以至于 Curve25519 选它？

本章回答前两个问题，第三个问题留到第 5 章（数据表示）和第 7 章（乘法）详细展开。

## 1.2 时钟算术：模运算的直觉

想想一个 12 小时制的时钟。3 点再过 11 个小时是几点？$3 + 11 = 14$，但时钟显示的是 2 点。
我们"回绕"了：$14 \bmod 12 = 2$。这里 $14 = 1 \cdot 12 + 2$，余数是 2。

**模运算就是"只保留余数"的算术。** 对正整数 $n$，我们说 $a \bmod n$ 是 $a$ 除以 $n$ 的余数：

$$a = q \cdot n + r, \qquad 0 \le r < n$$

其中 $q$ 是商，$r = a \bmod n$ 是余数。例如：

$$7 \bmod 3 = 1, \qquad 10 \bmod 4 = 2, \qquad 15 \bmod 5 = 0$$

**你其实早就熟悉模运算了。** C 语言中 `unsigned int` 的加法溢出后回绕，就是在做模
$2^{32}$ 的算术：`0xFFFFFFFFu + 1` 得到 0。唯一的区别是，密码学选择模一个**大素数**
$p$ 而不是 $2^{32}$，原因我们在 1.5 节和第 3 章会看到。

## 1.3 同余与模 $p$ 归约

设 $p$ 是一个正整数（密码学中是大素数）。我们称两个整数 $a, b$ 在模 $p$ 下**同余**，
记作

$$a \equiv b \pmod{p}$$

当且仅当存在整数 $k$ 使得 $a - b = kp$。换句话说，$a$ 和 $b$ 相差 $p$ 的整数倍。
例如 $17 \equiv 5 \pmod{6}$，因为 $17 - 5 = 12 = 2 \cdot 6$。

把任意整数 $a$ 变成 $[0, p-1]$ 中与其同余的数，这个过程叫**模 $p$ 归约**（reduction）。
比如 $23 \bmod 7 = 2$，就是把 23 归约到 2。

同余的一个重要性质是：**它和 $+$、$\cdot$ 兼容**。如果 $a \equiv b \pmod{p}$，那么对任何
整数 $c$：

$$a + c \equiv b + c \pmod{p}, \qquad a \cdot c \equiv b \cdot c \pmod{p}$$

这带来一个极其有用的推论：

> **可以在计算的任何一步先归约，结果不变。**

例如计算 $3 \cdot (5 + 6) \bmod 7$。可以先算 $5 + 6 = 11 \equiv 4 \pmod{7}$，再算
$3 \cdot 4 = 12 \equiv 5 \pmod{7}$；也可以一口气算完 $3 \cdot 11 = 33$，再归约
$33 \bmod 7 = 5$。两种方式结果相同。这被称为"提前归约不会出错"。

这一条性质是整个第 5–9 章实现策略的基石：我们不会在每一步都做完整的模 $p$ 归约
（那很贵），而是允许中间结果"膨胀"到超出 $[0, p-1]$，只在必要时才归约。只要保证
最终结果模 $p$ 正确即可。

## 1.4 为什么用固定宽度的整数

计算机里的数占固定数量的比特。如果 $0 < p \le 2^n$，那么 $[0, p-1]$ 中的任何数都能用
$n$ 个比特表示。于是：

- 所有中间结果都能放进固定大小的寄存器/数组，不担心"数太大存不下"；
- 运算结果仍然落在同一范围内，可以继续参与下一次运算；
- 一次运算的时间与输入值无关（这对抵抗时序攻击至关重要，见第 6 章）。

这正是"在模 $p$ 下计算"的动机：**把无限的可能压缩到有限、固定大小的空间里。**

## 1.5 Curve25519 的模数 $p = 2^{255} - 19$

Curve25519 使用素数

$$p = 2^{255} - 19$$

它的十六进制形式是

```
0x7fffffffffffffffffffffffffffffffffffffffffffffffffffffffffffffed
```

这个数有三个关键性质，后续章节会逐一用到：

1. **是素数**。这保证 $\mathbb{Z}_p$ 是一个域：每个非零元素都有乘法逆元（第 3 章）。
   可以用 SageMath 验证：`(2^255 - 19).is_prime()` 返回 `True`。
2. **255 位**。$2^{254} \le p < 2^{255}$，所以域元素可以放进 32 字节（256 位）里，
   且最高位（第 255 位）恒为 0。这解释了为什么第 5 章的 `unpack25519` 要强制
   `out[15] &= 0x7fff`。
3. **接近 $2^{256}$ 的幂**。$2^{256} = 2 \cdot (2^{255} - 19) + 38 = 2p + 38$，于是

   $$2^{256} \equiv 38 \pmod{2p}$$

   这个看似不起眼的恒等式是第 7 章乘法归约（神秘的 38）和第 5 章 `carry25519`
   的数学基础。现在先记住它，我们会在需要时回来解释。

## 1.6 C 代码：模运算的朴素实现

下面的代码演示基本模运算。注意两点：C 的 `%` 对负数可能产生负余数（例如
`-7 % 4` 在多数实现中是 `-3`），所以减法需要先加一个模数再取模；另外这里的
`mod_pow` 是"平方-乘法"（square-and-multiply），它将在第 3 章、第 8 章以更精致的
形式反复出现。

```c
#include <stdio.h>

/* 模 n 加法：结果保证在 [0, n-1] */
int mod_add(int a, int b, int n) {
    return (a + b) % n;
}

/* 模 n 减法：先加 n 再取模，避免 C 的 % 产生负余数 */
int mod_sub(int a, int b, int n) {
    return ((a % n) - (b % n) + n) % n;
}

/* 模 n 乘法 */
int mod_mul(int a, int b, int n) {
    return (a * b) % n;
}

/* 平方-乘法：计算 base^exp mod n，复杂度 O(log exp) */
int mod_pow(int base, int exp, int n) {
    int result = 1;
    base = base % n;
    while (exp > 0) {
        if (exp & 1)                 /* 当前二进制位为 1，乘入结果 */
            result = (result * base) % n;
        exp >>= 1;                   /* 处理下一位 */
        base = (base * base) % n;    /* 平方 */
    }
    return result;
}

int main(void) {
    int n = 7;
    printf("5 + 4 mod %d = %d\n", n, mod_add(5, 4, n));   /* 2 */
    printf("5 - 4 mod %d = %d\n", n, mod_sub(5, 4, n));   /* 1 */
    printf("5 * 4 mod %d = %d\n", n, mod_mul(5, 4, n));   /* 6 */
    printf("2^10 mod %d = %d\n", n, mod_pow(2, 10, n));   /* 2 */
    return 0;
}
```

> 警告：这段代码只用于理解概念。`int` 会在乘法中溢出（`a * b` 甚至 `(result*base)`），
> 而且 `%` 依赖实现。X25519 的真正实现（第 5 章起）必须仔细设计表示以避免溢出，
> 这正是我们使用 16-limb 表示的原因之一。

## 1.8 小结

- 模 $p$ 运算 = 只保留除以 $p$ 的余数；同余关系与 $+$、$\cdot$ 兼容。
- 我们可以在计算中途任意归约而不影响最终结果——这是"延迟归约"策略的理论依据。
- 固定宽度的整数让所有中间值都有确定的大小，且运算时间不依赖输入值。
- Curve25519 的 $p = 2^{255} - 19$ 是素数、255 位、且满足 $2^{256} \equiv 38 \pmod{2p}$。
